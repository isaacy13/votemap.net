# Open questions

Not locked. Solved (v0 only): [requirements.md](./requirements.md). Known accepted risks: [accepted-risks.md](./accepted-risks.md). Later (not solved, unfinished): [later.md](./later.md).

| | | Proposed solutions (not locked) |
| --- | --- | --- |
| Fees vs behavior | Restake 0%. Pay 1.5%. Public move 1.5%, shop move 5%. Early leave and expiry are both 5%, so waiting is not cheaper than bailing. Later only floats expiry at 1.5%. Quit-tax sends leftover to people you already paid when that amount is large enough. The auditable-trail score is visible only. Unsettled: whether those rates and that score make the wanted action cheaper than the unwanted one. **No new fee numbers.** |  |
| Friend pass-through | Two real Coinbase accounts. Vest 0, or a shop one of them owns. Same-account block does not see them. |  |
| Dead shop | Unspent credit stuck. |  |
| Politician claims a bounty | A politician, or a wallet they control, claims a payout for helping pass legislation or for another official act. v0 does not yet forbid that payee. Paying them for the act is the bribery case. A shop or family wallet they control is the same payment, not a workaround. Not a PEP form and not a lobbying filing. |  |
| PEP | v0 does not screen politically exposed persons. Coinbase country is not a PEP screen. Whether VoteMap should screen them, block them, or do nothing is not decided. This is not the politician-bounty row. |  |
| First stake sets class | 1 USDC as shop or public locks that URL’s class forever. Someone can front-run the class others meant. |  |
| Pay sig reused | Disperse and redeem need a votemap EIP-712 signature. The rules never give that signature a one-time nonce, a deadline, or the chain id. After a line is refilled, an old signature can pay the old payee again. |  |
| Revoked badge still pulls | Stake and disperse read the live Coinbase badge on the sending wallet. Early leave, expiry, and a public unlocked claim do not. They are wallet-only. After Coinbase revokes the badge, that wallet can still take leftover and unlocked public USDC. | 1. Early leave, expiry, and public claim also require a live US Coinbase badge. A revoked wallet cannot pull. 2. Those three stay wallet-only. A revoked wallet can still take the USDC. |
| Signer key pays out | The same-account block and the social-to-wallet lookup live in the signer, not in the contract. The contract accepts the votemap signature. Whoever has that key can sign a public pay to an address the user did not pick, including a wallet they control. A shop pay has to be a registered merchant, and the key holder can register one. |  |
| Cash-out off the trail | The named trail is one signer row on stake, disperse, move, and redeem. Public USDC leaves when the payee claims, and that claim is wallet-only. Early leave and expiry leave the same way. The page can show a pay to a person and never show the USDC leaving, or the staker taking the rest back. | 1. The named page lists stake, disperse, move, and redeem only. 2. Claim, early leave, and expiry get a named row on that page. Off-platform hops stay out. |
| Handle gets reused | Someone can change their handle. The phone number stays. The trail stores the handle from that moment, not the account. Nothing retires the old string. The next account to take it is the name on the old rows. | 1. A released handle is never issued again. Old rows can show a name that matches no account. 2. The string can be issued again. Old rows then read as the new account. |
| Catalog is not the charge | The catalog is off-chain. Redeem names a product and a price, and the factory pays that price. The chain cannot see the list. The buyer can be shown one price while the signature names another. After the tap, the pay is final. | 1. The signed price has to match that product’s catalog price. 2. The named price can differ from the catalog. The confirm screen is the check. |
| Payout wallet moves | Mapping a wallet takes a signature from that wallet. Nothing says the current payout wallet has to sign to move payout. A taken Google or Apple session can map a new wallet and set it as payout. The next shop redeem pays it. | 1. The current payout wallet has to sign before payout moves. 2. A logged-in session can set payout to a wallet it just mapped. |
| Lost phone | Redeem and disperse need the phone app and biometrics. Shop credit has no expiry, and the merchant cannot take it. Nothing lets a replacement phone enroll. A lost phone leaves the credit in the factory, and the merchant is unpaid. Leftover can still leave from the wallet. | 1. A new phone can enroll for the same account and redeem. A taken Google or Apple login can enroll one too. 2. The original phone is the only signer. Shop credit stays in the factory. |
| One post, two pots | X stores one pot per status id. Instagram allows `/p/{code}`, `/reel/{code}`, and `/{user}/p/{code}`, and those are not folded together. `threads.com` and `threads.net` are both allowed and are not folded together. The same post can be two pots, and the first dollar on each URL locks that URL’s class. | 1. The same Instagram code is one pot key across `/p/`, `/reel/`, and `/{user}/p/`. `threads.com` is stored as `threads.net`. 2. Each of those URL shapes stays its own pot. |
| Post is edited | After money is in, the author can change the caption. The issue page still shows the live embed. Browse keeps the first-stake line. New stakes hit the same pot against the new text. | 1. The issue page keeps showing the live embed after the caption changes. 2. When the live caption differs from the first stake, the card stays the snapshot. |
| Post goes private or deleted after money is in | Onlookers can’t see what the money was for. Voters look stuck. | 1. Keep the first-stake snapshot as the card forever. Live embed shows unavailable. Money rules unchanged. 2. Freeze new stakes and new disperse. Leftover can exit at 0%. Shop credit already issued stays. 3. Do both. |
| No stop | Hiding a row in the browse index leaves the pot payable. `registerMerchant` has no off switch. A post used to harass someone, or a shop listing an illegal good, can keep taking USDC. | 1. Pots and merchants stay payable. A hidden browse row does not stop the factory. 2. The signer refuses new stake, disperse, and redeem on a pot or merchant it marks. Leftover can still exit from the wallet. |
| Illegal-only moderation | Stop only what is strictly illegal: drugs, trafficking, paying for votes, and the same class of thing. Not a general content ban. Moderation has to be completely open. People can still see a muted post. The record of who muted it and why is public. Whether that record is on-chain is not decided. A politician claiming a bounty is already its own open row, not a decision that those posts are banned. | 1. Write the mute on-chain: who, which post, and why. The card stays readable and shows that it was muted. 2. Keep the same public record off-chain. Still not a hidden ban list. |
| Other people’s USDC | A stake cannot be pulled back. Stolen USDC can be staked, and a card reversal at an on-ramp can land after the USDC is already in the factory. Disperse and redeem pay that USDC onward. The person who lost it has no call in the contract. |  |
| Wrong network | The pay picker is a verified social on that pot’s network. The reward is for the person who did the work. That person can be verified only on one of the other three, or on none. They cannot be the payee. | 1. The payee has to be verified on the pot’s network. 2. Any verified social on the four networks can be the payee. Bio-only verify stays. |
| No taxpayer | Shop redeem and public claim pay a person in USDC. Legal name is not collected. The trail has a handle and a wallet. A payment that has to be reported has no legal name and no TIN on file. Research on what the law may require anyway, not a decision: [legal-reporting.md](./legal-reporting.md). |  |
| Rename splits the pot | Threads and TikTok pot keys include the @. A rename makes a new URL, so the same post is a second pot, and the first dollar on the new URL locks class. X can key the status id, so a rename there does not split the pot. | 1. Threads and TikTok keys keep the post id and drop the @, the way X can key the status id. 2. The @ stays in the key. A rename is a second pot. |
| Contract wallet | Mapping a wallet takes a signature from that address. That step has no contract-wallet check. An address that cannot produce a key signature cannot be mapped or set as payout. | 1. Only a key signature maps a wallet. A contract wallet cannot map or be the payout. 2. A signature the contract wallet itself verifies can map it, and that address can be the payout. |
| Factory upgrade | Upgrade power is unset. An upgrade can change where USDC goes. A factory that cannot change keeps a bad rule. | 1. The factory cannot be upgraded. A bad rule stays. 2. An admin can upgrade the factory. That key can change where USDC goes. |
| Direct USDC | A direct USDC transfer to the factory is not a stake, a credit, or a fee. The internal balances do not include it. The rules name no way to send it back. | 1. USDC that is not a stake, a credit, or a fee stays in the factory. No one can pull it. 2. The treasury can pull only that surplus. |
| Trail before the tx | The signer appends the trail row, including a tx hash, when it handles stake, disperse, move, and redeem. Nothing requires the tx to have landed. A reverted transaction can remain on the page. | 1. The row is written only after the tx is on Base. 2. The row is written when the signer submits. A reverted tx can stay on the page. |
| Trail social moves | The trail row stores the votemap handle from that moment. Social names are filled from the pay lookup. Nothing freezes the social @ on the row. After a rebind, an old payment can show a different Instagram, X, Threads, or TikTok. | 1. The row stores the social @ from that moment. A rebind does not change it. 2. The page uses the account’s current binds. Old payments show the new social. |
| No age check | Signup stores a birth year, and claim can write that year on-chain. The value is a year, not a day. Nothing reads it to block stake, disperse, redeem, claim, or shop register. | 1. Under 18 cannot stake, disperse, redeem, claim, or register a shop, and cannot be a payee. 2. The stored year does not block the money path. |
| Lost wallet | Early leave, expiry, and public claim are sent by the wallet that holds the position. Redeem is sent by the voter’s wallet. A lost key cannot send those transactions. The phone key is a different key. | 1. Those transactions stay on that wallet key. A lost key leaves the USDC in the factory. 2. A wallet already mapped on the same account can send early leave, expiry, and redeem. Public claim stays on the payee key. |
| Revoked shop still paid | Shop disperse and redeem check the Coinbase badge on the voter, the wallet that sends. They do not check the merchant payout wallet. A revoked shop can still be paid. | 1. Shop disperse and redeem also require a live US badge on the merchant payout wallet. A revoked shop cannot be paid. 2. The voter’s badge is the only check. A revoked shop can still be paid. |
| No factory pause | Nothing stops the whole factory at once. New stake, disperse, and redeem keep running when a rule is bad. A pause that also stops early leave and expiry would freeze leftover that the wallet can still take. | 1. There is no factory pause. Early leave, expiry, and public claim stay wallet-only. 2. An admin pause can stop new stake, disperse, and redeem. Early leave, expiry, and public claim still run. |
| Unclaimed balance | Shop credit has no expiry. A balance can sit for years. No rule reports that balance as unclaimed property or turns it over. | 1. A quiet balance stays under the factory rules. No unclaimed-property report. 2. A quiet balance can be reported to a state and turned over. The wait is not set. |

v0 fee numbers stay in [requirements](./requirements.md). This is not later. No new fee schedule.
